# VITA 발표용 데모 자료

발표 시연 순서 제안과, 실사용 데이터가 아직 부족해서 화면으로 직접 시연하기 어려운 부분(AI 이상
패턴 감지, 에너지 사용량 그래프, 자동화 규칙, 캘린더, 에너지 나무 성장, 알림함)을 위해 만든 더미
데이터 시나리오·화면 캡처 모음입니다.

## 중요: 이 데이터는 실제 Supabase에 들어간 적이 없습니다

캡처에 쓴 더미 데이터는 실제 프로덕션 DB(Supabase)에 넣었다가 지운 게 아니라, 애초에 **로컬에서만
띄운 가짜 백엔드**(FastAPI + 인메모리 더블)로 만들었습니다. 앱을 잠깐 이 가짜 백엔드에 연결해서
화면을 캡처한 뒤, 다시 원래 배포된 백엔드(AWS Lambda)를 보도록 되돌려 놨습니다. 그래서:

- 실제 사용자 데이터나 실제 기기 상태는 전혀 건드리지 않았습니다.
- 지금 앱을 켜면 이 문서의 더미 기기(에어컨/제습기/전기장판 등)는 보이지 않고, 원래 있던 실제
  Tapo 콘센트·조명만 보입니다.
- 캡처에 썼던 로컬 서버 스크립트는 저장소에는 포함하지 않았습니다(발표 화면 캡처용 1회성
  스크립트라 코드베이스에 남길 이유가 없음).

## 발표 시연 순서 제안

VITA 기획의 두 축("에너지 절약" + "화재 안전")을 순서대로 보여주고, 마지막에 가장 임팩트 있는
화재 감지 파트로 마무리하는 흐름을 추천합니다.

1. **스플래시** — 로고, 짧게
2. **메인 화면** — 실시간 온습도, 절전목표 진행률 → "한눈에 보는 우리 집"
3. **스마트홈 제어** — 실제 조명·Tapo 콘센트를 라이브로 켜고 끄기 → 실제 하드웨어가 진짜
   작동한다는 걸 초반에 보여줘서 신뢰 확보
4. **에너지 사용량** — 연/월/일 탭으로 사용량 추이와 전년·전월·전일 대비 증감률
5. **캘린더 + 자동화 규칙** — 외출·외박·요일별 루틴 트리거로 기기 자동 제어
6. **에너지 나무** — 절전 목표 달성도에 따라 자라는 나무 + 월간 숲 보기 (게이미피케이션)
7. **화재 예방 시스템 (클라이맥스)** — AI 이상 패턴 감지 → 방별 위험도 → 자동 대응 기록
8. **알림함** — 지금까지의 자동화/이상 감지 이벤트가 알림으로 쌓이는 것을 보여주며 마무리
9. (시간이 남으면) 안전 가이드북, 설정

## 더미 데이터 상세

### 1) AI 이상 패턴 감지 — 가상 기기 6종 (`07a`~`07c`)

`backend/app/anomaly/`가 계산하는 점수는 "무재실 상태(집에 아무도 없음) + 온도 급상승"이라는
공통 배경 위에, 기기별로 다른 이상 징후를 얼마나 더 얹었는지에 따라 등급이 갈리도록 설계했습니다.

| 가상 기기 | 등급·점수 | 걸린 조건 | 의도 |
|---|---|---|---|
| 에어컨 | 주의 · 45점 | 무재실 + 온도 급상승 (배경만) | 완전히 학습된 기기의 "가벼운 주의" 기본값 |
| 공기청정기 | 주의 · 45점 · **학습 중** | 무재실 + 온도 급상승 | 방금 등록돼 아직 14일 학습이 안 끝난 상태 |
| 제습기 | 주의 · 45점 | 무재실 + 온도 급상승 (배경만) | 에어컨과 동일한 배경 조건, 대조군 |
| 선풍기 | 경고 · 65점 | 배경 + **장시간 사용**(평소의 2.5배) | 배경 조건에 개인화된 이상 패턴 하나가 더해지면 등급이 뛰는 것을 보여줌 |
| 전기장판 | 위험 · 90점 · **자동 차단됨** | 배경 + 장시간 사용 + **전력 이상**(모드 평균 대비 47표준편차) | 조건이 여러 개 겹치면 "위험"까지 올라가 실제로 전원이 자동으로 꺼지고 자동 대응 기록에 남는 것까지 시연 |
| 헤어드라이기 | 경고 · 65점 · **학습 중인데도 경고** | 배경 + 장시간 사용 | 오늘 논의했던 "가끔 꽂아 쓰는 기기(헤어드라이기·충전기)"도 14일 학습이 안 끝났다고 무방비 상태로 방치되지 않고, 개인 데이터가 필요 없는 조건(장시간·무재실·온도)만으로 최소한의 보호를 받는다는 걸 보여주는 핵심 예시 |

방 카드의 "위험" 배지와 "전기장판 장시간 사용 시 화재 위험이 있어요" 문구는 이 AI 시스템과는
별개로, 기기 이름이 `안전 가이드북`의 고위험 기기 키워드(히터/전기장판/가스레인지/난로/온풍기)에
걸려서 뜨는 것입니다 — 학습 여부와 무관하게 항상 작동하는 별도의 즉시 판정 로직입니다.

### 2) 에너지 사용량 (`04a`~`04c`)

"에어컨"·"선풍기" 두 콘센트에 누적 소비전력(kWh) 값을 연도별(4개 연도)·최근 45일 일별·오늘
시간대별로 채워 넣어 3개 탭 전부 그래프가 그려지도록 했습니다. 연도별 수치는 실제 값이 아니라
"대략 이 정도씩 늘었다"는 느낌만 나도록 임의로 정한 값입니다(요청하신 대로 정밀하게 만들지
않았습니다).

### 3) 캘린더 / 자동화 규칙 (`05`, `06`)

캘린더는 이번 달에 외박(제주도 여행)·외출(장보기)·일반 일정(친구 방문) 각 1건과, 매일 반복되는
DAILY 항목 2개를 넣었습니다. 자동화 규칙은 그 캘린더 일정(외출·외박)을 트리거로 쓰는 규칙 1개,
DAILY 루틴을 트리거로 쓰는 규칙 1개, 취침 모드를 트리거로 쓰는 규칙(비활성 상태) 1개로
세 가지 트리거 종류를 전부 보여주도록 구성했습니다.

### 4) 에너지 나무 (`08`, `09`)

앱 설정의 절전 목표를 90kWh/월로 두고, 이번 달 1일부터 어제까지는 "목표 대비 25%/45%/70%/115%"
4가지 사용량 패턴을 순환시켜 넣었습니다(3번은 목표를 넘겨 성장이 멈추는 날도 일부러 섞음). 그
결과 이번 달 목표 달성률이 75%가 되어 나무가 다 자란 상태로 보이고, 월간 숲 보기에는 새싹·어린
나무·다 자란 나무가 고루 섞여 나옵니다.

### 5) 알림함 (`10`)

전부 실제 앱 코드(`FireSafetyContext`/`AutomationContext`/`SleepContext`)가 실제로 만드는
알림 제목·문구를 그대로 재사용했습니다 — 발표에서 "이런 상황이면 이런 알림이 옵니다"라고 보여줄
때 실제 문구와 다르지 않도록 하기 위함입니다.
